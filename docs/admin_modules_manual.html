Admin Modules

Presupuestos AP | Accounts Payable | Fonda Argentina

This guide walks through, one by one, the modules that appear under "PRESUPUESTOS" at /admin/, with real screenshots and what each field means. For the full expense-mapping logic and setting up from scratch, see the separate Initial Configuration Manual; this guide is the quick reference for "what does each screen do."

1. Sucursales (Branches)

Each branch maps to a company in Odoo (synced with scripts/sync_sucursales.py, not normally created here by hand). The field edited most often is Activa: only active branches show up as an option in the dashboard and PDF report filters.

The list lets you check/uncheck "Activa" right there and save several at once, without opening each one.

2. Categorias (Categories)

The top level: the P&L bucket each Tipo de gasto belongs to (typically "Costo de Ventas" / COGS and "Gasto Operativo" / opex). One field, Nombre; fully editable, not hardcoded.

3. Tipos de gasto (Expense types)

The catalog used everywhere else in the app (dashboard, reports, budgets). Each one belongs to a Categoria.

  • Nombre: what shows up on the dashboard and in reports.
  • Categoria: which P&L bucket it belongs to.
  • Descripcion: free text, reference only.

4. Catalogos: import / export (bulk load)

A dedicated screen at /admin/catalogos/ ("Catalogos" link in the admin's top bar) for loading Categorias, Tipos de gasto, and both mapping tables all at once from Excel, instead of entering them row by row. This is the recommended way to do the full initial setup.

  • Descargar plantilla (Download template): generates an .xlsx with 4 sheets (Categorias, Tipos de gasto, Categorias de producto, Cuentas contables). The first two sheets bring in whatever is already captured; the last two are filled live with the product categories and accounts that exist in Odoo. The "Tipo de gasto"/"Categoria" columns carry an Excel dropdown that only allows names already present in the matching sheet.
  • Importar plantilla (Import template): uploads the edited file. Behavior depends on the "Permitir carga inicial" flag (see "Configuracion de catalogos" below): while it's on, the import deletes the 4 current catalogs and replaces them completely; once used, it turns itself off and further imports only update (add/correct, never delete).
Important: while the initial-load flag is on and Presupuestos already exist that use a current expense type, the import cancels itself with an error message instead of deleting data in use - no need to worry about accidentally losing information.

Configuracion de catalogos

A single row in /admin/ holding the Permitir carga inicial flag. It turns itself off after a successful load; it's only reactivated here, by hand, when a full replacement is genuinely intended.

5. Cuentas contables -> tipo de gasto (Accounts -> expense type)

Mapping used for direct expenses (rent, maintenance, payroll, services...): the Odoo account itself already says which expense type it belongs to. Filled in automatically by running scripts/classify_odoo_catalog.py or by importing the catalog template (section 4); this is where you review/fix whatever was left unclassified.

The "Por tipo de gasto" filter on the right, with its blank option (-), is the fastest way to see which accounts are still unclassified.

6. Categorias de producto -> tipo de gasto (Product categories -> expense type)

Same mechanism as above, but for purchases tied to a purchase order: there the account is generic ("Goods Received Not Invoiced") and the expense type is decided by the purchased product's category instead of by the account.

7. Presupuestos (Budgets)

The monthly budget capture: one row per branch, expense type (optional), and month.

  • Sucursal, Mes, and Monto are required.
  • Tipo gasto left blank = "everything else": that amount is split evenly across whichever expense types don't already have their own row for that same month.
  • Mes can be any day inside the target month: it's normalized to the 1st on save.

8. Gastos reales (Actual spend)

Read-only: synced automatically from Odoo (scripts/scheduler.py, twice a day via Windows Task Scheduler) and never edited here. Useful for reviewing the line-by-line detail of what's already been classified, and for filtering by branch, expense type, or week.

9. Perfiles de usuario (User profiles)

Extends a Django user with their assigned branch. The role (what they can see) comes from Django Groups (Administrador, Usuario, Sucursal); the branch here only applies - and is only enforced - for users in the Sucursal group.

For the full setup from scratch (environment variables, syncing branches, the recommended order for these steps) see the Initial Configuration Manual. For day-to-day dashboard and report use, see the User Guide.
